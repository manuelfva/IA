# Active Context: Test-IA


## Current Work Focus


The project has been created with all core services implemented, a WebApp presentation layer, and the ICurrentUser identity abstraction. The memory bank is being initialized for the first time.


## Recent Changes


- **StatusCodePages POST Bug Fix**: Fixed ``UseStatusCodePagesWithReExecute`` incompatibility with POST requests � the middleware converts POST to GET during re-execution, causing anti-forgery validation failures and lost form data. Replaced with a custom ``UseStatusCodePages`` middleware that intercepts 403 responses and issues a 302 redirect to ``/AccessDenied``. Added ``[AllowAnonymous]`` attribute to ``AccessDeniedModel`` to prevent infinite redirect loops (without it, the redirect would trigger authorization again, creating a loop). Verified working. Build: 0 errors, 0 warnings. Tests: 26/26 passed.
- **AccessDenied Navbar Badge Fix (Remote)**: The navbar badge ``@Context.User.Identity?.Name`` was empty on the AccessDenied page when accessed remotely. Root cause: Windows Authentication (Negotiate/Kerberos) does not re-negotiate credentials on the 302 redirect for cross-machine requests. Fix: updated the StatusCodePages middleware to pass the authenticated username via redirect query string parameter (``userName``). Updated ``AccessDeniedModel.UserName`` to prefer the query string, falling back to HTTP context. Updated ``_Layout.cshtml`` navbar to use ``ViewData["UserName"]`` with fallback to ``Context.User.Identity?.Name``. Verified working (local + remote). Build: 0 errors, 0 warnings. Tests: 26/26 passed.
- **ICurrentUser Identity Abstraction and LDAP Bug Fix**: Refactored UserGroupAuthorizationService to use an ICurrentUser abstraction instead of directly resolving WindowsIdentity. Created ICurrentUser interface in Domain layer, ConsoleCurrentUser (reads WindowsIdentity.GetCurrent()) and WebCurrentUser (reads from HttpContext) implementations in Application layer. Fixed IsMemberOfGroup LDAP search bug - GetUserDistinguishedName was receiving DOMAIN\\Username instead of the short Username, breaking LDAP sAMAccountName lookups and causing IsMemberOfGroup to always return false. Fixed to use userSamAccountNameShort. Updated DI registrations in ConsoleApp/WebApp to include AddHttpContextAccessor() and all three ICurrentUser implementations. Updated all unit tests with a new CurrentUserMockHelper factory method. Build: 0 errors, 0 warnings. Tests: 26/26 passed.

- **Friendly Access Denied Page and Navbar Fix**: Replaced ``WindowsIdentity.GetCurrent()`` in ``_Layout.cshtml`` with ``Context.User.Identity?.Name`` to display the authenticated HTTP user instead of the process identity. Created ``AccessDenied.cshtml`` and ``AccessDenied.cshtml.cs`` � a styled error page shown when users are not members of the required AD group. Configured a custom ``UseStatusCodePages`` middleware in ``Program.cs`` that intercepts 403 responses and redirects to the Access Denied page. Added ``[AllowAnonymous]`` attribute to ``AccessDeniedModel`` to prevent infinite redirect loops. Added CSS styling in ``site.css``. Build: 0 errors, 0 warnings. Tests: 26/26 passed.

- **Self-Contained Deployment Package**: Added RuntimeIdentifier (win-x64) and SelfContained (true) properties to Test-IA.WebApp.csproj. Created scripts/publish-webapp.ps1 - a 6-step automated pipeline (clean, restore, build, test, publish, zip) that produces a timestamped deployment package (~46.5 MB) containing the full .NET 10 runtime, all application DLLs, configuration files, and a README-deploy.txt guide. Publish uses -p:PublishSingleFile=false because PublishSingleFile=true combined with self-contained causes >30s timeouts. Package supports deployment via direct executable run or NSSM Windows service. Updated README.md with full Deployment section. Build: 0 errors. Tests: 25/25 passed.

- **Extensible Logging Service with Sink Pattern**: Redesigned `LoggingService` to delegate to an `IEnumerable<ILoggingSink>` collection, enabling pluggable output targets (file, console, database, Event Log). Created `ILoggingSink` interface, `FileLoggingSink` (thread-safe append mode), `ConsoleLoggingSink`, and `LoggingPipelineFactory` (reads `appsettings.json` `Logging.Sinks` section). `LoggingService` now accepts both `ILogger<T>` and `IEnumerable<ILoggingSink>` — falls back to `ILogger<T>` only if no sinks are registered. `FileLoggingSink` includes `FormatMessage` method that handles both numbered placeholders (`{0}`, `{1}`) and named placeholders (`{Key}`, `{Value}`) matching `ILogger` behavior, with `HasNumberedPlaceholders` guard to avoid `FormatException` on literal curly braces (e.g., Distinguished Names). ConsoleApp and WebApp both configured with `Logging.Sinks.File` in `appsettings.json`. WebApp path uses `..\..\logs\test-ia.log` to resolve relative to solution root. Build: 0 errors, 0 warnings. Tests: 25/25 passed.
- **Navbar Displays Windows User Identity**: Replaced static "Active Directory" badge in `_Layout.cshtml` navbar with the current Windows user's identity (`DOMAIN\Username`). Uses `WindowsIdentity.GetCurrent()?.Name` directly in the Razor view — no new services, DTOs, or DI registrations required.
- **Remove Member from Group**: Added `RemoveMember` method to `IGroupMembershipWriter` interface and `GroupMembershipWriterService` implementation. Uses LDAP `ModifyRequest` with `DirectoryAttributeOperation.Delete` to remove a user's DN from a group's `member` attribute. WebApp Groups page (`Groups.cshtml` / `Groups.cshtml.cs`) now includes a "Remove Member from Group" section with two input fields (group samAccountName, member samAccountName), submit button (`name="Action"` `value="Remove"`). Form routing uses hidden `Action` field to distinguish Add vs Remove operations. Build: 0 errors. Tests: 25/25 passed.
- **User Group Authorization (ConsoleApp)**: ConsoleApp now performs authorization check at startup. Reads `Authorization.RequiredGroup` from `appsettings.json`. If the group doesn't exist (`MissingGroupException`) or the user is not a member (`AccessDeniedException`), the application logs an error and exits. If the user is a member, proceeds to run the real AD operations. Build: 0 errors. Tests: 25/25 passed.
- **User Group Authorization (WebApp)**: WebApp now uses ASP.NET Core policy-based authorization. Added `GroupAuthorizationRequirement` (Domain layer), `GroupAuthorizationHandler` (Application layer) that resolves `IUserGroupAuthorizationService` via `IServiceScopeFactory` within a DI scope. Registered via `AddPolicy("RequiredGroup", policy => policy.Requirements.Add(new GroupAuthorizationRequirement(settings.RequiredGroup)))`. `AddNegotiate()` for Windows Authentication (Kerberos/NTLM). Non-member users receive 401 Unauthorized. Build: 0 errors. Tests: 25/25 passed.
- **User Search Panel Expansion**: `UserDto` expanded from 6 to 14 properties to match the Update User panel attributes (`UserAttributeMapper` now maps all 14 LDAP attributes and `GetDisplayValues()` returns all 14). ConsoleApp and WebApp User Search panels now display all 14 LDAP attributes dynamically. Build: 0 errors. Tests: 25/25 passed.
- **WebApp Section Redesign**: `Index.cshtml` restructured into two distinct sections (Users and Groups) with visual differentiation. Users section (purple accent) contains User Search + User Update cards. Groups section (green accent) contains Group Search card. Section headers include icons, titles, and descriptions. CSS uses gradient backgrounds, colored borders, and glow effects for visual distinction. Responsive grid layout adapts to different screen sizes. Build: 0 errors. Tests: 25/25 passed.
- **Dynamic Console Display**: ConsoleApp uses `IAttributeMapper.GetDisplayValues()` to render attributes dynamically via `foreach` loops instead of hardcoded `LogInformation` calls. Adding new attributes only requires updating the mapper, not the console app.
- **Dynamic WebApp Display**: WebApp `Index.cshtml` uses `@foreach` loops over `Model.UserDisplayValues` and `Model.GroupDisplayValues` instead of hardcoded HTML table rows. Both ConsoleApp and WebApp share the same `GetDisplayValues()` pattern, ensuring consistent dynamic rendering across all presentation layers.
- **Footer Text Alignment Fix**: Footer text alignment do not works in `site.css`. Root cause was a CSS syntax error in `.members-list li::before { content: '\''2022'; ... }` which caused the browser to stop parsing all subsequent CSS rules including the footer styles. Fixed the malformed content value to `content: '\2022';`. Build: 0 errors.

- **AccessDenied Page Security Refactoring**: Refactored `AccessDenied.cshtml` to be completely independent from `_Layout.cshtml` to prevent information leakage to unauthorized users. The page now uses `Layout = null` and includes its own full HTML structure (`<!DOCTYPE html>`, `<html>`, `<head>`, `<body>`, CSS link). Removed all sensitive data exposure: `@Model.UserName` (unauthorized user's identity), `@Model.RequiredGroup` (internal AD group name), and `@Model.HttpStatusCode` (technical detail). Replaced with a generic message: "Your account does not have permission to access this application. Please contact your Active Directory administrator to request access." Simplified `AccessDeniedModel` to remove `IHttpContextAccessor`, `IOptions<AuthorizationSettings>` dependencies, and all exposed properties (`UserName`, `RequiredGroup`, `HttpStatusCode`). Updated `Program.cs` StatusCodePages middleware to stop passing `userName` query string parameter. Build: 0 errors, 0 warnings. Tests: 26/26 passed.
